# داده ماندگار چارت تصویری — افزوده به پایه ۰٫۳

سه تصویر کاربر بدون تغییر در image-1.png، image-2.png و image-3.png نگه‌داری می‌شوند. charts.json داده قابل اجراست؛ شامل نام، کد یا کد نامشخص، واحد، ترتیب نیمسال، روابط، خانه‌های انتخابی و وضعیت بازبینی. تصویر و داده با هش به هم متصل‌اند. برای اجرا به گفت‌وگوی ChatGPT یا اینترنت نیاز نیست.

- ۱۳۹۵ تا ۱۴۰۰: تصویر سوم، گرایش نرم‌افزار.
- ۱۴۰۱ و ۱۴۰۲: تصویر اول با عنوان کلی «۱۴۰۱ به بعد».
- ۱۴۰۳ به بعد: تصویر دوم، طبق تأیید صریح کاربر؛ بر عنوان کلی تصویر اول مقدم است.

خط پیوسته پیش‌نیاز و خط‌چین هم‌نیاز است. جای درس در ترم به‌تنهایی شرط اخذ محسوب نمی‌شود. داده‌های قبلی در backend/data برای تکمیل جدول گزینه‌های خانه‌های کلی استفاده می‌شوند؛ تصویر منبع اصلی درس‌های نام‌برده‌شده است. ردیف‌های چند بسته با یک شناسه در هر گروه یک بار نمایش داده می‌شوند. گروه‌های تمرکز با یکدیگر ادغام نمی‌شوند.

روابط بازخوانی‌شده با relationship_reviewed=true مشخص‌اند؛ باقی روابط پیش از پیشنهاد آماده نیازمند بازبینی‌اند. اعلام اخذنشده بودن به نمره وابسته نیست؛ هر سابقه اخذ، حتی صفر، مردودی و بی‌نمره، آن درس را از فهرست «هنوز برنداشته» خارج می‌کند. این به معنی فارغ‌التحصیلی یا قبولی نیست. اخذ مجدد مردودی‌ها موضوع این فهرست نیست.

کد دقیق مقدم است. کد متفاوت با نام یکسان یا اختلاف با کد تصویر فقط «تطبیق نامطمئن» ایجاد می‌کند و به قبولی یا هم‌ارزی تبدیل نمی‌شود. کد نامرتبطِ یک درس، باقی فهرست را پنهان نمی‌کند. اختلاف 30128/30045 برای برنامه‌نویسی وب و 291478/291503 برای آزمایشگاه ابزارهای طراحی همچنان نیازمند تأیید است.

تصویر دوم کد ندارد؛ کدهای CSE/SCI صرفاً از داده موجود می‌آیند و رسمی بودن آن‌ها با تصویر تأیید نشده است. برای عمومی‌ها و پروژه بدون کد، کد ساخته نشده و «کد تأیید نشده» نمایش داده می‌شود. کد ورودی دیگر خودکار منتقل نمی‌شود.

options.json مسیر عضویت در گروه‌های اختیاری/تخصصی/تمرکز و گزینه‌های / را مشخص می‌کند. این فایل سهم باقی‌مانده فارغ‌التحصیلی را تعیین نمی‌کند. اگر گزینه‌ای قبلاً اخذ شده باشد از گزینه‌های اخذنشده حذف می‌شود؛ از آن نتیجه گرفته نمی‌شود که کل سهم گروه تکمیل شده است. مسیرهای عمومی مثل درس سایر رشته‌ها که جدول نام و کد ندارند، به درس ساختگی تبدیل نمی‌شوند. متن مسیرها در visual_summary.selection_notes حفظ شده است.

پیشنهاد آماده فقط یعنی شروط ثبت‌شده چارت احراز شده‌اند. هم‌نیازهای پیشنهادی باید با هم اخذ شوند. ارائه، ظرفیت، سقف واحد، سهم گروه، انتخاب تمرکز و استثناهای آموزشی از این تصاویر به دست نمی‌آیند. شرط «اخذ» واحد یا نیمسال بدون تعریف رسمی تفسیر نشده است.

policy.json با تأیید صریح کاربر حد قبولی ۱۰ را برای همه درس‌ها و ورودی‌ها ثبت کرده است. نمره ۱۰ و بالاتر برای احراز قبولی پیش‌نیاز استفاده می‌شود. برای فعال‌سازی براساس قانون واقعی، passing را به شیئی شامل minimum_grade، zero_is_final و source (شناسه مصوبه رسمی) تغییر دهید. این تنظیم هیچ کارنامه‌ای ذخیره نمی‌کند و هر تحلیل دوباره خوانده می‌شود. نمونه صرفاً ساختاری، نه قانون دانشگاه:

```json
{"passing":{"minimum_grade":10,"zero_is_final":false,"source":"شماره و تاریخ مصوبه معتبر"}}
```

دانشجوها و نتایج تحلیل کش یا در فایل داده پایه ذخیره نمی‌شوند. اصل کد API محلی، توکن نشست و مجوزهای افزونهٔ ۰٫۳ تغییر نکرده‌اند.
